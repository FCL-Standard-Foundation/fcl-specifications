# Security

## Reporting

Please report **security** or **privacy** issues privately to:

**info@fclstandard.org**

Do **not** open a public GitHub issue with sensitive exploit details, personal data, private keys, credentials, or other confidential material.

## Coordinated disclosure

We prefer **coordinated disclosure**. After private report:

1. Acknowledge receipt when feasible.
2. Assess impact on registries, verifiers, profile resolution, tokens/receipts, or related tooling described by the specs.
3. Work toward a fix or specification clarification before public detail is shared, where that does not conflict with urgent public-interest needs.

Public discussion of **non-sensitive** security design questions (for example clarifying conformance expectations already visible in the drafts) may use the Security / Privacy issue template, which points reporters back here for sensitive details.

## Scope notes

These specifications describe a permission data model and related registry/verifier concepts. Many security controls for production registries are still open issues in FCL-CORE. Reports that identify gaps, ambiguities, or dangerous interpretations in the drafts are welcome.
